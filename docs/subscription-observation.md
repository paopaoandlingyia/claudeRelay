# 订阅额度观测约定

最后确认：2026-10-09。本文件记录长期分析口径，不固定某次拟合的数值或排名。

## 目标与报告口径

对外售卖以 API 价格为参照，实际消耗的是订阅额度。观察普通输入、输出、5m/1h
缓存写入、缓存读取的消耗差异：**获得相同的 $1 API 等价价值，谁消耗的订阅额度
最少，谁的变现效率最高。** API 等价价值不是实际收款或净利润。

- 主表：`每 $1 API 等价价值的消耗 = 每百万 token 的订阅利用率消耗估计 / 每百万 token 的 API 价格`。
  单位是利用率百分点/美元，越低越好；不再把普通输入强制归一为 1。
- 按模型、订阅档位及观测阶段比较，注明样本量、数据完整性和拟合稳定程度。
  不强行假定所有模型共享动作权重；样本混合时，明确说明采用的模型倍率假设。
- 辅助相对效率表可把 5m 写入固定为 1×；普通输入归一化表仅供历史对照。
- 保留整体核对指标：`窗口 API 等价价值 / 观测利用率增量`。
  未耗尽窗口也参与观察，不推算其耗尽价值或把增量补到 100%。
- 动作消耗来自混合请求的拟合，不是逐动作官方账单。基准不稳定、参数贴近边界或
  缺少独立变化时，不可靠排名，不将接近零的拟合结果解释为免费。
  做完整性、窗口筛选和混合模型的敏感性检查；不能仅凭拟合变化断言官方调整规则。

## 数据与阶段边界

- 默认通过已有 SSH 别名 `racknerd-latency` 只读分析服务器，脚本经标准输入执行，
  数据留在远端内存，不再下载数据库或导出包到本地。
- SQLite：`/var/lib/docker/volumes/claude-relay-data/_data/claude-relay.db`。
  使用只读连接和事务快照；不要使用会忽略 WAL 的 `immutable=1`。
- 主窗口筛选沿用：已结束且留出约 5 分钟缓冲、首次利用率在 0–2% 内、
  观测增量至少 10 个百分点。缺失/不完整数据单独标注并做对照，未知利用率不当作零。
- 用户已清理之前的数据，以当前保留的数据为本轮起点；每次报告注明实际时间范围。
- 按请求发生时间匹配版本化价格，并在单条请求层面判断长提示词档位，不能用
  小时或窗口 token 总量判定单次请求的价格。历史回溯与按现价重估需明确区分。
- 2026-10-09 20:16（北京时间）部署了 API 价值明细修复及 Sonnet/Haiku 5.5 定价支持。
  当天的成熟窗口主要来自部署前，不当作部署后效果。小时旧数据无法核对分档的标为未完整定价。
- 始终使用上游原始 usage 研究订阅消耗；下游拒绝计费倍率等响应调整不混入该口径。

日常观测不授权修改调度、收费、服务器配置、部署或清理数据。
